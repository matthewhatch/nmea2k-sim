# Captured vcan0 engine traffic

M7 adds `m7-fault.log` and `m7-fault.json`: actual SocketCAN traffic from a
bounded simulator process, with nine PGN 127489 samples. Low fuel pressure is
injected at model seconds 4–6 and recovers to 3 bar. Reproduce with
`env/bin/python scripts/capture_fault.py` on a configured vcan0, reserving source
and unique number 238. The script independently assembles fast packets and
checks raw field offsets. See [M7 model assumptions and scenarios](../FAULTS.md).

`engine-default.log` is actual `candump -L` output, recorded during the
2026-11-13 M0–M2 alignment work. It is not encoder-generated synthetic log text.
The capture uses source address 205 (0xCD) to coexist with an existing source-35
demo without stopping it. It contains 113 classic extended CAN frames over
12 seconds: 61 rapid messages plus 13 four-frame dynamic packets.

Reproduce from the repository root after installation and vcan setup:

```sh
env/bin/python scripts/capture_vcan.py --output /tmp/engine-default.log
```

The script only uses a verified kernel `vcan0` interface, starts candump with
exact engine/source filters, runs a bounded simulator, and checks the capture
completed. It neither creates an interface nor touches physical CAN. Reserve
source 205 during capture. Defaults/environment are explicitly overridden:

```sh
candump -L -n 113 vcan0,09F200CD:1FFFFFFF,09F201CD:1FFFFFFF
env/bin/python -m nmea_sim.simulator --channel vcan0 --source-address 205 --rapid-hz 5 --dynamic-hz 1 --count 61
```

Those two commands run concurrently; the script manages that lifecycle.
Timestamps naturally differ when regenerated. Do not overwrite the committed
fixture without reviewing it and rerunning its replay checks.

Offline replay through the receive-only consumer's Decoder:

```sh
env/bin/python -m pytest -q tests/test_capture_fixture.py
```

Expected observations:

| Observation | Expected result |
| --- | --- |
| IDs | 09F200CD / 09F201CD, priority 2, source 205 |
| Initial rapid bytes | 00 00 00 FF FF FC FF FF |
| Initial decoded engine | off, instance 0, RPM 0, trim -4, boost unavailable |
| Script | off to starting to idle to acceleration |
| Last rapid RPM | approximately 1560 at 12 seconds |
| Initial dynamic values | oil 0 Pa; coolant 293.15 K; voltage 12.6 V; fuel 0 L/h; hours 100 |
| Last engine hours | 100 + 10/3600 (running since 2 seconds) |
| Unsupported sensors | unavailable, not fabricated numeric measurements |
| Dynamic transport | 26-byte payloads, four frames, sequence wraps 7 to 0 |

The test parses the saved log, feeds actual frames to the consumer's decoder,
checks counts, cadence, state changes and unavailable values, and cross-checks
rapid values using raw byte offsets. This is reproducible local evidence, not
third-party parser validation, device discovery or NMEA certification.

## M3 discovery and independent decode

`m3-device.log` is a real 195-frame `candump -L` capture from verified vcan0,
recorded on 2026-11-13. `m3-device.events.json` records 14 checked protocol steps.
`m3-device.canboat.jsonl` is actual independent CANboat output, not generated by
this project's decoder. `m3-device.canboat.validation.json` records counts and
the SHA-256 of the input capture.

Reproduce the live exchange (reserve 210, 211 and 220):

```sh
env/bin/python scripts/capture_device.py --output /tmp/m3-device.log
```

The script runs a separate simulator (unique number 210, device instance 17,
engine instance 2), a requesting/contending CAN peer and candump. It verifies:

- Initial source 210 claim, followed by at least 250 ms before engine TX.
- Directed and global requests for NAME, product/configuration information and both PGN lists.
- Directed unsupported requests and heartbeat requests receive NACK at requester 220.
- Unsupported global and other-destination requests produce no response.
- A higher NAME loses: our device reasserts 210 and waits before resuming engine TX.
- A lower NAME wins: our device claims 211 and waits before resuming engine TX.
- Identity requests and periodic heartbeat work at the new source.

CANboat revision: **2a42e004e01094b25049dddf737277f33c324ff1**, reported version
**9.2.0**. Build its unmodified C analyzer and converter outside this repository:

```sh
git clone https://github.com/canboat/canboat.git /tmp/canboat-m3
git -C /tmp/canboat-m3 checkout 2a42e004e01094b25049dddf737277f33c324ff1
make -C /tmp/canboat-m3/analyzer
make -C /tmp/canboat-m3/candump2analyzer
```

Decode and compare (adjust platform directory if needed):

```sh
env/bin/python scripts/validate_canboat.py \
  --analyzer /tmp/canboat-m3/rel/linux-x86_64/analyzer \
  --converter /tmp/canboat-m3/rel/linux-x86_64/candump2analyzer \
  --capture docs/captures/m3-device.log \
  --output /tmp/m3-device.canboat.jsonl
```

This invokes the independent converter/parser, then compares their output with
our consumer's decoded wire values. It checks priority, NAME fields, serial and
model/configuration strings, separate supported lists, NACK destination/PGN,
heartbeat interval/counter, engine instance/RPM/trim and modeled dynamic fields.
CANboat standard units differ: oil pressure is bar, coolant is Celsius, and
running time is seconds; comparison explicitly converts Pa/K/hours.

Result: **79 messages matched across 9 PGNs**: 2 acknowledgements, 13 requests,
8 claims, 4 lists, 4 heartbeats, 3 product, 2 configuration, 34 rapid and 9 dynamic.
Input SHA-256:
`1141b3483f5e738a9bb47c637d5533baba4dbb6045c4bfd0f19af982d4a6bfdf`.

The user-approved manufacturer 2046 is unassigned and virtual-test-only. CANboat
omits its manufacturer lookup because it is out-of-range; this is explicitly
checked, not represented as a valid assigned manufacturer. Product code,
certification/version/load fields are likewise unavailable. No real manufacturer,
certification level or hardware measurement is invented.

Offline regression checks need no CAN sockets or CANboat installation:

```sh
env/bin/python -m pytest -q tests/test_device_protocol.py tests/test_device_capture.py
```

They compare the saved independent output and raw capture, and verify claim
waits/conflict recovery from actual timestamps. The external tool command above
regenerates the evidence independently; fixture tests alone are not a new
third-party execution. Physical-bench/Garmin/certification acceptance remains M4.


## M4 full-cycle capture

`m4-cycle.log` records 464 actual frames across a 51-second full engine cycle:
256 rapid messages and 52 dynamic messages, source 230, engine instance 1.
`m4-cycle.canboat.jsonl` is independent CANboat 9.2.0 output using `-json -nv`
(the numeric lookup value validates named engine instances). Its validation
report includes all modeled field ranges and input/output/binary hashes.

Reproduce with `env/bin/python scripts/capture_cycle.py --output /tmp/m4-cycle.log`
on verified vcan0 with source 230 reserved. Capture and validation commands,
field-level results, tolerances, provenance and physical limitations are in
[the M4 report](../interop-m4.md). Offline regression:

```sh
env/bin/python -m pytest -q tests/test_cycle_capture.py
```

The full cycle independently matches RPM 0–4500, trim -4–12 percent, oil pressure
0–400000 Pa, fuel 0–35 L/h, voltage 12.6–14.2 V and running time that stops while
off. This evidence concerns virtual CAN; it does not establish physical or
Garmin compatibility.


## M5 native instruments

`m5-dashboard-live.png` is an actual native Qt X11/xcb screenshot in an isolated
Xvfb display. `m5-dashboard-live.json` is the application's explicitly requested
single diagnostic snapshot, not a simulator-state export or historical store.
The dashboard and simulator ran in separate processes over vcan0 at source 237,
engine instance 1. Recorded readings: 2961 RPM, 25.71 C, fresh telemetry.
`m5-dashboard-live.validation.json` records the method, Qt version and both hashes.

Reproduce with `env/bin/python scripts/capture_dashboard.py --output-dir /tmp/dashboard-demo`.
Default capture uses native Qt offscreen; `--platform xcb` uses an available X11
display (or Xvfb). See [dashboard installation and verification](../dashboard.md)
for system-library requirements and troubleshooting. Physical CAN was not used.
